# Prompts Context — Asistente WhatsApp (Aleja Escobar)

## Proposito
Documenta el sistema de prompts del asistente de agendamiento de citas por WhatsApp.
Este archivo es la fuente de verdad para editar contenido de prompts (persona, instrucciones, descripciones de tools).

## Los 7 Estados de Conversacion

Cada estado define que instrucciones recibe el LLM y que tools tiene habilitadas.
Fuente: `src/services/agentic/prompts/state_instructions.py`

| Estado | Descripcion | Objetivo del LLM | Tools principales |
|--------|-------------|-------------------|-------------------|
| `NO_ACTIVE_REQUEST` | Inicio de agendamiento | Pedir nombre, motivo, modalidad. Llamar `submit_consultation_reason_for_review` | `set_contact_name`, `submit_consultation_reason_for_review` |
| `AWAITING_CONSULTATION_DETAILS` | Profesional pidio mas detalle | Pedir detalles adicionales del motivo, no repetir pregunta base | `submit_consultation_reason_for_review` |
| `AWAITING_PATIENT_CHOICE` | Horarios propuestos, esperando seleccion | Recordar elegir por numero de opcion | `confirm_selected_slot_and_create_event` |
| `COLLECTING_CONFIRMATION_DATA` | Slot seleccionado, completar perfil | Pedir TODOS los campos faltantes en UN mensaje | `confirm_selected_slot_and_create_event` |
| `AWAITING_CONSULTATION_REVIEW` | Motivo enviado, esperando revision profesional | Responder preguntas generales, no avanzar flujo | `handoff_to_human` |
| `AWAITING_PAYMENT_CONFIRMATION` | Pago pendiente de aprobacion | Dar info de pago (Nequi o Zelle segun ubicacion), no repedir comprobante | `handoff_to_human` |
| `POST_BOOKING_FOLLOWUP` | Cita reservada exitosamente | Preguntar si necesita algo mas, cerrar sesion cuando termine | `close_session`, `handoff_to_human` |

Tools disponibles en TODOS los estados: `set_contact_name`, `handoff_to_human`, `cancel_active_scheduling_request`.

## Flujo de Ensamblado del Prompt

```
AgentProfile.system_prompt (Firestore)     ← Base: persona, estilo, contexto profesional
        |
        v
PromptAssembler.compose_full_prompt()
        |
        +-- RuntimeContextSection          ← Estado actual, request_id, modalidad, preferencias
        +-- StateInstructionsSection        ← Instrucciones especificas del estado (tabla de arriba)
        +-- PatientProfileSection           ← Datos conocidos del paciente (evita repreguntar)
        +-- EnabledToolsSection             ← Lista de tools habilitadas este turno
        |
        v
"### Runtime Context (Generated by Backend)"
        |
        v
Prompt final enviado al LLM
```

Archivos del pipeline:
- `src/services/agentic/prompts/prompt_assembler.py` — Ensambla base + secciones
- `src/services/agentic/prompts/prompt_section.py` — ABC para secciones
- `src/services/agentic/prompt_builder.py` — Orquesta el build completo

## Reglas de Estilo (Persona Aleja Escobar)

- Tono: directo, calido, conciso. No formal en exceso.
- Formato: WhatsApp (`*bold*` para enfasis, bullets con `•`).
- Longitud: max 2-3 oraciones por mensaje. Responder la pregunta primero.
- Idioma: espanol colombiano natural.
- Prohibido: filler ("espero que estes bien"), mencionar procesos internos, describir tools.
- Nombre del paciente: usar naturalmente, no en cada mensaje.

## Archivos Editables (Boundary del Agente Prompts)

### PUEDE editar
- `docs/sp.txt` — Contenido completo del system prompt base (persona, flujo, precios, horarios)
- `src/services/agentic/prompts/state_instructions.py` — SOLO las listas de strings retornadas por `_instructions_for_state()` (el texto de instrucciones, no la estructura del codigo)
- `src/services/agentic/tool_registry.py` — SOLO los valores `description=` de cada `FunctionDeclarationDTO` (el texto que guia al LLM sobre cuando/como usar cada tool)

### NO PUEDE editar (territorio del agente backend)
- `prompt_section.py` (ABC)
- `prompt_assembler.py` (logica de ensamblado)
- `runtime_context_section.py` (inyeccion de datos de runtime)
- `enabled_tools_section.py` (inyeccion de lista de tools)
- `patient_profile_section.py` (inyeccion de datos del paciente)
- `prompt_builder.py` (orquestador del build)
- Cualquier archivo en `guards/`, `graphs/`, `tool_handlers/`
- `parameters_json_schema` y `name` en `tool_registry.py` (esos son del agente backend)

## Sync Firestore <-> sp.txt

`docs/sp.txt` es la referencia local de desarrollo. En produccion, el system prompt se lee de `AgentProfile.system_prompt` en Firestore.

Flujo de sync:
1. Editar `docs/sp.txt` localmente
2. Correr tests: `uv run pytest tests/services -q`
3. Actualizar Firestore via `PUT /v1/agent/system-prompt` (ver `docs/API_ENDPOINTS.md`)

Si no existe AgentProfile en Firestore, se usa `default_system_prompt` de settings como seed.

## Testing

Despues de cualquier cambio de prompt:
- Correr: `uv run pytest tests/services -q`
- Para cambios en `state_instructions.py`: revisar tests en `tests/services/agentic/` que ejerciten el conversation graph
- Validar que el texto suena natural en espanol y cumple las reglas de estilo
